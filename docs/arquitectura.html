2. Persistencia y modelo

Esquema v2

users, professionals, categories, services, availability, appointments y app_session. Las claves foráneas vinculan las entidades.

Integridad de horarios

Un índice parcial impide dos citas pendientes/confirmadas en el mismo slot. La reserva valida solapamientos por duración tanto del profesional como del cliente en una transacción exclusiva. Las citas canceladas liberan el horario.

Inicialización

SQLiteProvider corre el esquema con PRAGMA user_version, aplica las migraciones y su versión en una transacción, crea el seed idempotente y mantiene datos entre reinicios. Renueva diez días de disponibilidad al abrir la app y consultar horarios; elimina disponibilidad vencida.

Autenticación mock

Cuenta local, sesión y contraseña hasheada para demostración. Sin backend, sal, control de intentos ni recuperación; no es apta para producción.

5. Relaciones de datos

Un usuario profesional tiene un perfil; el perfil tiene servicios y disponibilidad. Cada cita une un cliente, un profesional y un servicio. La sesión referencia un usuario. Las categorías clasifican perfiles y servicios.
